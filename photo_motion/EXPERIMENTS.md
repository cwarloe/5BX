# Photographic experiment run provenance and credit ledger

The standalone `photo_motion.experiments` module records the **exact declared inputs and observed costs of individual photographic video-generation attempts**. It does **not** generate video, purchase credits, schedule work, approve exercise form, or replace the process advisor's travelers and Kanban.

Every intent, actual-charge receipt, and artifact receipt carries an irreversible-in-this-tool release state:

`HOLD_FOR_HUMAN_FORM_AND_RELEASE_REVIEW`

The human reviewer must inspect the **actual continuous MP4**, not a four-panel montage, before any downstream release. These records are cost and provenance evidence, **not** technical/form QA passes. `photo_motion.inspect`, contact/temporal/identity QA and the motion-contract checks remain complementary diagnostics.

## Private storage and authorization

Use a **private directory outside every Git checkout**. Its JSON records contain the *verbatim submitted prompt*, which can contain sensitive information. Never add raw references, generated photos/videos, prompt files, or this private ledger directory to Git. The experiment store contains hashes, locators, estimates, and charge IDs; it does not copy media bytes.

Initialize only after receiving an **explicit provider-specific maximum credit allowance** from Charles. Example placeholders below are **not an approved spend**:

```bash
# Replace these placeholders after budget authorization; this command spends 0 credits.
python3 -m photo_motion.experiments init \
  --store /private/5bx-photo-experiments \
  --provider "PROVIDER_NAME_FROM_BUDGET_APPROVAL" \
  --credit-limit "PROVIDER_CREDIT_CAP"
```

The cap is immutable within the ledger. A separate provider gets a separate ledger and separately approved cap; credits are **not** converted or pooled. To change a cap, retain the old evidence and obtain a new documented authorization and separate store. Do not erase old runs to reclaim space or credits.

Run `python3 -m photo_motion.experiments status --store /private/5bx-photo-experiments` to see actual spend, pending reservations, available credits and attempt count. A pending reservation stays pending even for a failed attempt until the provider's **actual** charge is recorded. If a real charge exceeds the estimate, the truthful available balance can become negative and all additional reservations are blocked.

## One actual generation attempt

Save the provider input exactly as submitted, *including manual edits*, in an untracked UTF-8 file. The module stores the literal text and SHA-256 of the original file bytes (including original line endings). It **cannot itself prove** that those exact bytes were transmitted to the provider; the operator is accountable for that assertion. It must never relabel an autogenerated draft prompt as a submitted prompt.

Write a private request JSON like this, replacing every placeholder with the *actual* values:

```json
{
  "schema_version": 1,
  "attempt_key": "scissor-photo-v8-actual-attempt-001",
  "exercise_id": "chart1-scissor-jump",
  "spec_path": "photo_motion/specs/chart1-scissor-jump.json",
  "submitted_prompt_file": "/private/5bx-photo-experiments/inputs/actual-submitted-prompt.txt",
  "input_assets": [
    {
      "role": "approved-identity-anchor",
      "locator": "private://identity/anchor-original",
      "local_path": "/private/5bx-video-archive/identity-original.png"
    },
    {
      "role": "movement-reference",
      "locator": "private://movement/scissor-source",
      "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
    }
  ],
  "provider": "PROVIDER_NAME_FROM_BUDGET_APPROVAL",
  "model": "EXACT_PROVIDER_MODEL_VERSION",
  "settings": {
    "duration_seconds": 6,
    "seed": null,
    "aspect_ratio": "16:9",
    "camera": "locked-off 35 mm photographic framing"
  },
  "estimated_credits": "CREDITS_RESERVED_FOR_THIS_ATTEMPT"
}
```

`attempt_key` identifies **one intentional paid generation call**. Replaying the identical request with the same key is idempotent and creates no new reservation. A real additional generation, even with identical inputs, **must use a new attempt key** and consume a second reservation. A changed input under a previously used key fails closed. The run ID is the full SHA-256 of canonicalized request data (including the ordered source hashes, exact prompt text/hash, spec hash, model, settings, cost estimate and key).

Each input reference needs a `role` and stable `locator`. When `local_path` is present, the module hashes bytes itself and checks any declared SHA-256 against them. If the reference is inaccessible, a previously known SHA-256 is required and is explicitly labeled `declared_unverified`; **an unchecked link alone is never recoverable evidence**. Preserve the original identity and movement reference files in the private archive. An AI-descended frame is not an automatically approved identity anchor.

```bash
python3 -m photo_motion.experiments reserve \
  --store /private/5bx-photo-experiments \
  --request /private/5bx-photo-experiments/inputs/attempt-001.json
```

The resulting JSON provides `run_id`. **Reserve before calling a paid generator**; a reservation is a guardrail, not authority to spend beyond what Charles approved. Do not assume model determinism: a repeat of the same recipe can still produce different video output. Store each real output independently.

After the provider reports its charge (including zero, if verified), record it once:

```bash
python3 -m photo_motion.experiments settle \
  --store /private/5bx-photo-experiments \
  --run-id FULL_64_CHAR_RUN_ID \
  --actual-credits "ACTUAL_PROVIDER_CHARGE" \
  --provider-generation-id "EXACT_PROVIDER_RUN_OR_EDITOR_ID" \
  --outcome COMPLETED
```

If the generation failed, use `--outcome FAILED` and the **actual reported charge**. If the actual charge is unknown, leave the reservation open; do not invent zero. A second settlement with different values is rejected rather than silently rewriting history.

Hash the real output (without copying or modifying it):

```bash
python3 -m photo_motion.experiments artifact \
  --store /private/5bx-photo-experiments \
  --run-id FULL_64_CHAR_RUN_ID \
  --artifact /private/5bx-video-archive/scissor-attempt-001.mp4 \
  --role raw-generated-video \
  --locator private://video/scissor-attempt-001
```

Each artifact receipt records SHA-256, byte size, role and stable locator. A changed file results in **another** receipt; the old one survives. Track human review separately in the project's established process.

## Reproducibility and failure boundaries

- The ledger captures the exact declared *recipe* and factual output hashes, but cannot guarantee the video model will recreate the same pixels or validate exercise mechanics.
- The module uses operating-system locks, atomic exclusive file creation, `fsync`, and read-only ledger records to prevent accidental overwrite and simultaneous credit over-reservation. Its records are **not** an independently hosted, tamper-proof audit log: a filesystem administrator can still delete or rewrite them. Preserve backed-up snapshots externally if adversarial integrity or disaster recovery is required.
- The budget cap applies to the one provider and the one ledger. It does not look up a live provider balance, prevent someone from using the provider outside this tool, or authorize a paid call.
- Linux/POSIX `fcntl` locks are used. Do not share one active store among unsupported operating systems or unreliable distributed/network filesystems without first verifying exclusive writes and locking semantics.
- No command has an `APPROVE`, `RELEASE`, `PUBLISH`, or `GENERATE` operation.

Run synthetic regression coverage with `python3 -m unittest photo_motion.tests.test_experiments -v` or the complete suite via `python3 -m unittest discover -s photo_motion/tests -v`. No paid services or production media are used in these tests.
